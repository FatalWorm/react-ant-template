# План перехода на Модульную (Domain-Driven) архитектуру

Данный документ описывает пошаговый план рефакторинга текущего проекта на модульную архитектуру, ориентированную на предметные области (Domain-Driven), с учетом использования React 19, Zustand, React Query и Ant Design.

## Главные правила Модульной архитектуры

1. Приложение разделяется на независимые бизнес-модули (домены).
2. **Изоляция:** Модуль (например, `users`) инкапсулирует всё необходимое: UI-компоненты, Zod-схемы, Zustand-стор, React Query хуки и ky-запросы.
3. **Слабая связность:** Модули **не должны** импортировать внутренности других модулей напрямую. Связь — только через `shared` или на уровне `pages`.
4. **Public API (index.ts):** Каждый модуль обязан иметь `index.ts`, экспортирующий только публичные части. Внешний код пишет `import { LoginForm } from '@/modules/auth'`, а **НЕ** `from '@/modules/auth/components/LoginForm'`.
5. **Стратегия общих типов:** Типы, используемые в нескольких модулях (например, `UserId`, `PaginationParams`, базовый ответ API), выносятся в `src/shared/types/`. Дублирование типов между модулями недопустимо.

---

## Этап 0: Подготовка инфраструктуры

1. **Настройка Alias-ов:**
   В `vite.config.ts` и `tsconfig.json` убедиться, что настроен алиас `@/` на `src/`.
2. **Создание структуры:**
   Создать в корне `src/` базовые директории:
   - `core/` (инициализация, глобальные провайдеры)
   - `shared/` (переиспользуемый UI-кит, утилиты)
   - `modules/` (бизнес-домены)
   - `pages/` (сборка маршрутов)

---

## Этап 1: Выделение ядра (Core)

_Слой `core` отвечает за глобальную настройку приложения._

1. **HTTP Клиент:** Перенести инициализацию `ky` (настройку базового URL, перехватчики для токенов) в `src/core/api/httpClient.ts`.
2. **React Query:** Вынести настройку `QueryClient` в `src/core/api/queryClient.ts`.
3. **Глобальный стейт:** Если есть глобальное состояние (например, тема оформления, локаль), перенести Zustand стор в `src/core/store/appStore.ts`.
4. **Роутинг:** Перенести конфигурацию `react-router-dom` в `src/core/router/`.

---

## Этап 2: Выделение общих компонентов (Shared)

_Слой `shared` содержит глупые (dumb) компоненты и хелперы, не привязанные к бизнес-логике._

1. **UI Kit:** Обернуть компоненты Ant Design (если они кастомизируются через `styled-components`) и перенести в `src/shared/ui/`.
2. **Утилиты:** Перенести функции для работы с датами (`luxon`), парсеры и форматоры в `src/shared/utils/`.
3. **Глобальные типы:** Вынести общие интерфейсы (например, типы пагинации, базового ответа API) в `src/shared/types/`.

---

## Этап 3: Создание и изоляция бизнес-модулей (Modules)

_Для каждой предметной области (например, `auth`, `users`, `dashboard`) создается своя папка в `src/modules/`._

Для каждого модуля выполняем следующие шаги миграции:

1. **Схемы и Типы (Schemas & Types):**
   Перенести Zod-схемы валидации и типы TypeScript в `src/modules/[moduleName]/schemas/` (например, `loginSchema.ts`).
2. **API Запросы (API):**
   Функции, делающие `ky.get`, `ky.post` для данного домена, вынести в `src/modules/[moduleName]/api/`.
3. **Стейт-менеджмент (State):**
   - **Серверное состояние:** Создать кастомные хуки поверх React Query (например, `useLoginMutation`, `useGetUsersQuery`) в `src/modules/[moduleName]/hooks/`.
   - **Локальное состояние:** Если модулю нужно сложное состояние формы или UI, создать локальный Zustand-стор в `src/modules/[moduleName]/store/`.
4. **UI Компоненты (Components):**
   Перенести формы (`react-hook-form` + `zodResolver`) и другие компоненты отображения данных в `src/modules/[moduleName]/components/`. Они должны использовать хуки из папки `hooks` своего модуля.

---

## Этап 4: Сборка страниц (Pages)

_Страницы собирают компоненты из разных модулей и привязывают их к URL._

1. Перенести страницы в `src/pages/[PageName].tsx`.
2. Страница работает как контейнер. Импорт компонентов — **только через `index.ts` модуля**:

   ```typescript
   // ✅ Правильно
   import { UserList } from '@/modules/users';
   import { UserStats } from '@/modules/analytics';

   // ❌ Неправильно — «глубокий» импорт нарушает инкапсуляцию
   import { UserList } from '@/modules/users/components/UserList';
   ```

3. Страница не содержит прямых вызовов `ky` или бизнес-логики. Все данные — через хуки модулей.

---

## Этап 5: Очистка и настройка Точки входа

1. Настроить `src/main.tsx` (или `App.tsx`) так, чтобы он был максимально чистым.
2. Он должен только оборачивать приложение в провайдеры (React Query Provider, Ant Design ConfigProvider), импортированные из `src/core/`.

---

## Чек-лист завершения миграции

- [ ] Бизнес-логика разбита по папкам внутри `src/modules/`.
- [ ] **Каждый модуль** имеет `index.ts` (Public API), экспортирующий только публичные части.
- [ ] Нигде нет «глубоких» импортов из модулей (`@/modules/auth/components/...`), только `@/modules/auth`.
- [ ] Общие типы (используемые в 2+ модулях) вынесены в `src/shared/types/`, а не дублируются.
- [ ] В `src/shared/` нет бизнес-логики, Zod-схем доменов или запросов к API.
- [ ] Модули независимы: `modules/a` не импортирует из `modules/b`.
- [ ] Все формы используют `react-hook-form` и локализованы в `components/` своего модуля.
- [ ] Серверное состояние обрабатывается через `React Query` в `hooks/` каждого модуля.
- [ ] Приложение успешно запускается и билдится (`npm run build`).
