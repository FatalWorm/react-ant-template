# Оптимизация сборки (Bundle Optimization)

Данный документ описывает все архитектурные решения, направленные на минимизацию размера итогового бандла, ускорение загрузки приложения и эффективное использование браузерного кэша.

---

## 1. Code Splitting: Разделение бандла на чанки

Вместо одного монолитного JS-файла мы разбиваем сборку на **изолированные vendor-чанки**. Это позволяет браузеру кэшировать тяжёлые зависимости отдельно от кода приложения — при обновлении бизнес-логики пользователю не придётся заново скачивать React или Ant Design.

### Стратегия чанков (`vite.config.ts → manualChunks`)

| Чанк                | Содержимое                                   | Причина выделения                                         |
| ------------------- | -------------------------------------------- | --------------------------------------------------------- |
| `vendor-react`      | `react`, `react-dom`, `react-router`         | Ядро фреймворка, обновляется крайне редко                 |
| `vendor-antd`       | `antd`                                       | Основная UI-библиотека, самый тяжёлый пакет (~300 KB)     |
| `vendor-ant-design` | `@ant-design/*` (иконки, утилиты, цвета)     | Внутренние зависимости antd, меняются вместе с ним        |
| `vendor-rc`         | `rc-*` (rc-table, rc-select, rc-tree и т.д.) | Низкоуровневые React-компоненты, на которых построен antd |
| `vendor-luxon`      | `luxon`                                      | Библиотека дат, независима от остального кода             |
| _(код приложения)_  | Всё из `src/`                                | Часто меняющийся бизнес-код, не кэшируется долго          |

### Принцип: почему именно так?

```text
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ vendor-react │   │ vendor-antd  │   │   app code   │
│   ~140 KB    │   │   ~300 KB    │   │    ~50 KB    │
│  кэш: долго  │   │  кэш: долго  │   │  кэш: мало   │
└──────────────┘   └──────────────┘   └──────────────┘
       ↑                  ↑                  ↑
   Обновляется        Обновляется        Обновляется
   раз в год          раз в месяц        каждый деплой
```

> При каждом деплое пользователь скачивает заново **только** изменившийся код приложения (~50 KB), а vendor-чанки (~500+ KB) подтягиваются из кэша браузера.

### Лимит размера чанка

```typescript
chunkSizeWarningLimit: 1000, // 1 MB
```

Стандартный лимит Vite (500 KB) вызывает ложные предупреждения из-за размера `antd`. Мы подняли его до 1 MB, так как чанк `vendor-antd` после Brotli-сжатия весит значительно меньше.

## 2. Сжатие: Brotli

Мы используем плагин `vite-plugin-compression` для предварительного (build-time) сжатия всех статических файлов алгоритмом **Brotli** (`.br`).

```typescript
// vite.config.ts
viteCompression({
  algorithm: 'brotliCompress',
  ext: '.br',
});
```

### Почему Brotli, а не Gzip?

| Параметр            | Gzip    | Brotli    |
| ------------------- | ------- | --------- |
| Степень сжатия      | ~70%    | ~80%      |
| Поддержка браузеров | 99%+    | 97%+      |
| Скорость сжатия     | Быстрее | Медленнее |

Brotli сжимает **на 15-20% лучше**, чем Gzip, но работает медленнее. Поскольку мы сжимаем на этапе сборки (а не на лету), скорость сжатия не критична — зато пользователь получает файлы меньшего размера.

> **Важно:** для работы Brotli web-сервер (Nginx, Caddy) должен быть настроен на раздачу `.br` файлов при наличии заголовка `Accept-Encoding: br`.

## 3. Lazy Loading: Отложенная загрузка

### Страницы

Все страницы загружаются **лениво** через `React.lazy()`. Это означает, что при первом заходе на сайт браузер скачивает только код текущей страницы, а остальные подгружаются по мере навигации.

```typescript
// app/router/routes.tsx
const HomePage = lazy(() => import('@/pages/Home'));
const AboutPage = lazy(() => import('@/pages/About'));
const LoginPage = lazy(() => import('@/pages/Login'));
const RegisterPage = lazy(() => import('@/pages/Register'));
```

Пока страница загружается, пользователь видит глобальный `<Suspense fallback={<LoadingFallback />}>` — спиннер Ant Design на полный экран.

### React Query DevTools

DevTools загружаются **только в dev-режиме** и тоже лениво:

```typescript
// app/providers/index.tsx
const ReactQueryDevtools = env.isDev
  ? lazy(() =>
      import('@tanstack/react-query-devtools').then((mod) => ({
        default: mod.ReactQueryDevtools,
      })),
    )
  : () => null;
```

> В production-сборке DevTools полностью отсутствуют — ни одного лишнего байта.

## 4. Анализ бандла: Bundle Visualizer

Для визуального анализа размера и состава бандла используется плагин `rollup-plugin-visualizer`. После каждой production-сборки (`npm run build`) он генерирует интерактивную HTML-карту.

```typescript
// vite.config.ts
visualizer({
  filename: 'dist/stats.html',
  open: false, // Измените на true, чтобы карта открывалась автоматически
});
```

### Как использовать

```bash
npm run build
# Открыть файл в браузере:
open dist/stats.html    # macOS
xdg-open dist/stats.html # Linux
```

Карта показывает:

- **Размер каждого модуля** (до и после сжатия)
- **Состав каждого чанка** (какие пакеты в него попали)
- **Визуальные аномалии** — если какой-то пакет неожиданно большой, он сразу бросается в глаза

> **Рекомендация:** запускайте анализ после добавления новых тяжёлых зависимостей, чтобы убедиться, что они попали в правильный чанк или были выделены в отдельный.

## 5. Оптимизация шрифтов

В `index.html` шрифты Google Fonts (`Inter`, `Outfit`) подключены с использованием паттерна **preconnect**, который устанавливает раннее соединение с серверами шрифтов ещё до того, как парсер доберётся до CSS:

```html
<link
  rel="preconnect"
  href="https://fonts.googleapis.com"
/>
<link
  rel="preconnect"
  href="https://fonts.gstatic.com"
  crossorigin
/>
<link
  href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=Outfit:wght@500;600;700&display=swap"
  rel="stylesheet"
/>
```

- `display=swap` — текст отображается сразу системным шрифтом, а после загрузки подменяется на кастомный (нет "белого экрана" из-за шрифтов)
- Загружаются **только нужные начертания** (400, 500, 600, 700), а не весь шрифт целиком

## 6. Чеклист перед production-деплоем

- [ ] Запустить `npm run build` — убедиться, что сборка проходит без ошибок
- [ ] Открыть `dist/stats.html` — проверить, что нет аномально больших чанков
- [ ] Проверить наличие `.br` файлов в `dist/` — Brotli-сжатие работает
- [ ] Убедиться, что `env.isDev === false` — DevTools не попадут в прод
- [ ] Проверить настройки web-сервера — раздача `.br` файлов включена
