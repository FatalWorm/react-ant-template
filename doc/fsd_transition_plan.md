# План перехода на Feature-Sliced Design (FSD)

Данный документ описывает поэтапный план рефакторинга текущей кодовой базы проекта на архитектуру Feature-Sliced Design (FSD) с учетом используемого стека (React 19, Zustand, React Query, Ant Design).

## Главные правила FSD

### 1. Однонаправленные зависимости

Слои могут зависеть только от нижележащих слоев.
Порядок слоев (от самого верхнего к самому нижнему):

```
app → pages → widgets → features → entities → shared
```

> **Важно:** `app` — это верхний слой в иерархии зависимостей (он знает обо всём),
> а `shared` — нижний (не знает ни о чём выше себя). Порядок **миграции** в плане ниже обратный
> (начинаем с нижних слоёв), но иерархия зависимостей остаётся неизменной.

### 2. Изоляция слайсов

Слайсы (папки внутри слоя) не могут импортировать друг друга.
Например, `features/auth` не может импортировать `features/cart`.

### 3. Public API (index.ts)

Каждый слайс обязан иметь файл `index.ts`, который экспортирует только то,
что разрешено использовать снаружи. Внешние файлы импортируют из `@/features/auth`,
а **НЕ** из `@/features/auth/ui/LoginForm`.

## Этап 0: Подготовка инфраструктуры

1. **Настройка Alias-ов:**
   Убедитесь, что в `vite.config.ts` и `tsconfig.json` настроен алиас `@/` на папку `src/`.
2. **Линтинг (Рекомендуется):**
   Установить и настроить плагины ESLint для контроля зависимостей, чтобы предотвратить нарушение архитектурных границ.
   - Плагины: `eslint-plugin-import`, `@conarti/eslint-plugin-feature-sliced`.
3. **Создание структуры папок:**
   Создать внутри `src/` пустые директории: `app`, `pages`, `widgets`, `features`, `entities`, `shared`.

---

## Этап 1: Формирование слоя Shared (Общие модули)

_Shared слой не должен содержать бизнес-логики. Только инфраструктура и переиспользуемые UI-компоненты._

1. **API Клиент:** Перенести настройку `ky` в `src/shared/api/httpClient.ts`.
2. **UI Kit:** Перенести кастомные обертки над Ant Design (кнопки, инпуты со своими styled-components стилями) в `src/shared/ui`.
3. **Конфиги и утилиты:** Перенести общие хелперы (форматирование дат через `luxon`, парсеры) в `src/shared/lib` или `src/shared/utils`.
4. **Типы:** Перенести глобальные TypeScript типы, не привязанные к конкретным сущностям, в `src/shared/types`.

---

## Этап 2: Выделение слоя Entities (Сущности)

_Entities — это базовые бизнес-сущности без сложной логики. Они не знают о фичах._

Для каждой ключевой бизнес-сущности (например, `user`, `product`):

1. **Модели данных (Zod):** Перенести Zod-схемы в `src/entities/[name]/model/schemas.ts`.
2. **Сторы (Zustand):** Перенести базовое состояние (Zustand + Immer) в `src/entities/[name]/model/store.ts`. (В сторах храним только данные сущности, без логики запросов на сервер).
3. **UI Компоненты:** Создать простые компоненты отображения сущности (например, `UserCard`, `ProductItem`) в `src/entities/[name]/ui`.
4. **API запросы:** Вынести базовые функции-запросы (ky) для получения/обновления сущностей в `src/entities/[name]/api/`.

---

## Этап 3: Создание слоя Features (Фичи / Бизнес-сценарии)

_Features — это конкретные действия пользователя (например, регистрация, добавление в корзину)._

1. **Формы:** Перенести логику форм (`react-hook-form` + `zodResolver`) в `src/features/[featureName]/ui/`. (Например: `LoginForm`).
2. **React Query:** Перенести хуки мутаций и запросов, относящиеся к бизнес-действию, в `src/features/[featureName]/api/`.
3. **Оркестрация:** Если фича требует обновления состояния Zustand после мутации React Query, логика связывания должна находиться здесь, в кастомных хуках (в слое `features`).

---

## Этап 4: Сборка слоя Widgets (Виджеты)

_Widgets — самостоятельные блоки, объединяющие Entities и Features._

Стандартная структура виджета:

```text
src/widgets/[widgetName]/
  ui/        # Компонент виджета
  model/     # Локальный стейт виджета (если нужен)
  lib/       # Вспомогательные функции
  index.ts   # Public API — единственная точка экспорта наружу
```

1. **Сложные компоненты:** Перенести или создать сложные составные компоненты (например, `Header`, `Sidebar`, `UserProfileWidget`) в `src/widgets/[name]/ui/`.
2. **Композиция:** Виджеты импортируют фичи и сущности **только через их `index.ts`**. Например, `Header` импортирует `User` из `@/entities/user` и `LogoutButton` из `@/features/auth`.
3. **Public API:** Создать `src/widgets/[name]/index.ts` и экспортировать только компонент виджета.

---

## Этап 5: Сборка слоя Pages (Страницы)

_Pages — это просто контейнеры (layout), которые компонуют виджеты вместе._

Стандартная структура страницы:

```text
src/pages/[pageName]/
  ui/        # Компонент страницы
  index.ts   # Public API (экспортирует компонент страницы для роутера)
```

1. Переместить компоненты страниц из старой структуры в `src/pages/[pageName]/ui/Page.tsx`.
2. Заменить прямое использование форм/логики на страницах вызовами виджетов **через их `index.ts`**: `import { Header } from '@/widgets/header'`.
3. Страница не должна содержать бизнес-логики, только компоновка UI из виджетов.
4. Роутер в слое `app` импортирует страницы через их `index.ts`: `import { LoginPage } from '@/pages/login'`.

---

## Этап 6: Настройка слоя App (Инициализация приложения)

_Слой App настраивает глобальные провайдеры и роутинг._

1. **Providers:** Собрать все провайдеры (React Query Provider, Ant Design ConfigProvider, Styled-Components ThemeProvider) в один компонент `src/app/providers/index.tsx`.
2. **Routing:** Настроить `react-router-dom` в `src/app/routers/`. Роутер должен импортировать страницы из слоя `pages`.
3. **Global Styles:** Перенести глобальные стили (`index.css` или глобальные компоненты `styled-components`) в `src/app/styles/`.
4. **Точка входа:** Обновить `main.tsx` (или `index.tsx`), чтобы он импортировал инициализированное приложение из слоя `app`.

---

## Чек-лист проверки после перехода

- [ ] Папки на верхнем уровне `src/` строго соответствуют FSD (`app`, `pages`, `widgets`, `features`, `entities`, `shared`).
- [ ] **Каждый слайс** имеет `index.ts` (Public API), экспортирующий только публичные части.
- [ ] Нигде в кодовой базе нет «глубоких» импортов вида `@/features/auth/ui/LoginForm` — только `@/features/auth`.
- [ ] Слои импортируют только из нижележащих слоев (проверить ESLint-плагином).
- [ ] Слайсы одного слоя не импортируют друг друга.
- [ ] Отсутствуют циклические зависимости.
- [ ] Приложение успешно собирается (`npm run build`).
- [ ] Тесты Vitest/RTL проходят успешно.
